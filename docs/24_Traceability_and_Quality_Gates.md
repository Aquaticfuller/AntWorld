## 2. 质量分级

- **Mechanism Valid**：状态结构、事件时序、质量守恒、ID/几何一致性通过自动测试。
- **Biologically Plausible**：多种子统计与定性生物学现象一致，但参数未必实测标定。
- **Species Calibrated**：参数来自有明确物种/实验条件/单位的文献或数据，并经交叉验证。
- **Visual Prototype**：画面和镜头可观察，并不自动代表机制正确。
- **Gameplay Ready**：完成存档/输入/统计/稳定性体验；不是 S0 目标。

**不能把 Mechanism Valid 描述成 Species Calibrated。** 不允许让大模型生成一段漂亮解说来替代真实记录的证据。

## 3. 测试准入条件

每个阶段至少：

1. Debug 与可用的 Release 构建无未解释失败；Cpp 警告可见且关闭高风险编译诊断。
2. 自动化测试结果保留完整命令、原始输出摘要、测试环境版本。
3. 现有测试不能因为新功能而不经审查直接删除或跳过。
4. 守恒检查、事务回滚、事件 ID 唯一性和世界隔离优先于渲染效果。
5. 所有生物常数附带来源状态与单位；虚构 fixture 不得被报告为实验数据。
6. 每阶段完成后更新架构 ADR、Changelog、待决问题和下一批依赖。

## 4. 失败时的行为

- 任一核心不变量失败：保存最小复现实验/seed，标记 FAIL，不得宣称该阶段完成。
- 编译器/系统不支持某项测试：标记 NOT RUN 并解释原因，不能算 PASS。
- 遇到规格冲突：按优先顺序 `当前用户明确指令 > 01已确认决策 > 16 ADR > 17–24 详细契约 > 较早建议`，提出一个 ADR，**不悄悄选更容易的实现覆盖用户意图**。
- 遇到未知生物参数：使用明确标记的工程 fixture，记录后续标定任务；不得凭直觉填写“黑园蚁真实阈值”。

## 5. 定量性能预算（首轮只测，不做未经验证的承诺）

每阶段报告：模拟秒数/现实秒数、p50/p95 的 `AdvanceTo` 耗时、常驻/峰值内存、事件处理量、checkpoint 大小与耗时、几何重建/导航更新时间。Unity 另报 FPS、渲染帧时间及原生桥接耗时；Game Master 另报 API 频率/延迟/成本，绝不混算为核心模拟吞吐。

P0 预计只做小规模实验；500–2,000 蚂蚁是后续压力目标，20,000+ 是长期目标，不应写进 S0 的验收门槛。
