# S6.3.3.1 performance instrument and timing protocol

This protocol follows the two retained version-1 probes and precedes the version-2 confirmation and all timing. It applies to the final Windows Release build of this branch. The previous five-point-five growth observation remains preliminary.

## Instrument finding and version 2

The restricted probe could query native processor times and could not open the PDH processor counter. The unrestricted host probe reproduced `2147485654` (`0x800007D6`, `PDH_CALC_NEGATIVE_DENOMINATOR`) on logical CPU 0 eight times and on logical CPU 2 three times. Every such sample had positive PDH clock advance and an idle increment larger than that advance. The corresponding native per-CPU deltas on those two processors were available. Microsoft defines the status as a calculation error. The raw observations do not establish the provider-level cause.

Both version-1 probes also have nonmonotonic or stationary idle and kernel deltas on other logical processors. At every such interval the changes in kernel and idle time were equal. Across all CPUs and both probes the recorded non-idle kernel time and user time increments were nonnegative. These observations support testing an explicit non-idle-time instrument. The old verdicts remain INCONCLUSIVE.

Version 2 computes CPU occupancy as `100 * (delta(KernelTime - IdleTime) + delta(UserTime)) / delta(wall time)` using native times in 100 ns units and the independent QPC wall interval. It retains all raw native counters, the rejected idle-ratio field, original PDH results and raw statuses, and `GetSystemTimes`. No rejected PDH value is replaced or clamped. A complete version-2 sample needs the expected native byte count, nonnegative non-idle kernel and user deltas on every logical CPU, and a busy duration within the measured interval plus two 15.625 ms accounting ticks. Raw quantization overshoot stays in the output. The interval for each 1 s sample must fall within 0.8 to 1.2 s. Native totals are cross-checked against aggregate `GetSystemTimes`.

Before admission, repeat the exact pinned 20/12/12/16 s host probe once with version 2. Require every measured interval to be valid, both own-core pulse medians at least 80% and opposite-core medians below 35%, the median absolute aggregate error at most 2 percentage points, and median absolute disagreement with valid paired PDH in unpulsed periods at most 10 points on each measured CPU. Record failures as they occurred. If this confirmation is inconclusive, no formal timing proceeds under this protocol.

## Admission and workload

Pin the benchmark to the same first performance-core logical CPU and keep the collector off that entire physical core. Keep the historical 512 and 2048 dense and dispersed contact workloads, 128 diagnostic rows, and endogenous-birth workload. Use three sessions for each kind, with each prior ABBA/BAAB schedule, warm-up flag, durations, seeds and ordering intact. Freeze all schedules and the current contact/birth executable SHA-256 values together before admission. Compare completed rows against historical workload and continuation hashes and retain the unchanged core work and fact counts.

For each session take 60 one-second admission samples under version 2. Require every sample to be valid. System load from `GetSystemTimes` and selected logical load from the confirmed non-idle wall instrument each require p50 <=10% and p95 <=20%. Retain original PDH values alongside the new measurement. Require AC, saver off, fresh HWiNFO timestamps within -2 to 10 s, and numeric package temperature, package power and effective frequency. Up to three attempts per session are permitted at least five minutes apart. Record all attempts and stop the batch if admission exhausts or a started session fails. A started session is never repeated. No other agent build, experiment, extraction, analysis or test overlaps timed collection.

Sample CPU occupancy, frequency, power status, process time and collection cost during each timed run. Keep the localized HWiNFO source snapshots in ignored local storage. Publish the mapped English CPU frequency, temperature, power and throttle fields for all logger samples in the recorded interval plus 3 s before and after, with source hashes. Keep all slow rows and in-run disturbances. A missing thermal interval longer than 10 s or absent bracketing produces an incomplete qualification with all measured samples retained.

## Analysis and verdict

The formal dense advance p50 ratio for 2048 over 512 remains <=6 for each gate, with the original hierarchical session/block bootstrap and paired median as supporting uncertainty. Preserve every native phase sample, including setup, advance, encode, restore, CPU/cycles and the matching work counts. This is the existing workload. TD-11 is a separate care-enabled density study and does not enter the legacy gate. Require all three verified, fully instrumented sessions for a PASS or FAIL on a workload. Otherwise record INCONCLUSIVE and leave historical outcomes intact.
