# S5 durable saves, history and analytics

Protocol frozen before implementation. Approved baseline: S4 commit 214fce398a29d26507e21c75f4f78f1485527e6b, CONDITIONAL PASS. Branch: codex/s5-durable-history. Preserve all 89 tests and every earlier raw archive. S6 integrated ecology, Unity and Game Master are excluded.

## Decisions

- ADR-S5-01: keep the C++ core independent of storage. An application library owns a pinned SQLite connection and writes a complete canonical checkpoint, event cursor, new committed facts, entity records, command receipts and metric observations in one transaction. Use WAL, synchronous FULL and foreign-key checks. Acknowledgement follows COMMIT. No separate file rename is part of this transaction. Pin upstream SQLite 3.54.1 by its published archive hash; builds must also work from a verified local archive.
- ADR-S5-02: retain the newest two complete generations by default; keep committed factual history and metric observations. Recovery loads only a complete generation and validates its checkpoint and evidence correspondence. Never reconstruct continuation from a high-level event journal. Refuse unsupported schema, mismatched world, divergent event prefixes, stale saves and corrupted data. Do not silently roll back a durably acknowledged world to an older generation on corruption. An older generation may be inspected explicitly; it is not permission to overwrite the current timeline.
- ADR-S5-03: world-qualified IDs and uint64 values must remain exact through SQLite; do not silently narrow them to signed integers or floating point. Evidence uses actual EventId, ScheduledId, actor/related entity, resource, geometry edit/parcel, time and revision. Seeded adult records describe creation, not an invented biological birth. Rejected actions are recorded outcomes, never successful transfers. Individual tracking and analytics do not feed behavior choices.
- ADR-S5-04: add a minimal typed, explicitly invoked food-placement command solely to verify the persistence/idempotency contract. The core validates a legal input boundary, bounds/clearance, quantity and capacity; a successful command has a stable 128-bit ID, immutable payload and one actual fact/resource. Identical retries return the existing receipt; changed payload conflicts. An application-owned candidate is durably committed before replacing the live runtime, so failure cannot expose a partly saved command. No agent, permission policy, autonomous intervention or broad tool API is introduced. Schema 6 adds the receipt ledger; physics stays 7 because existing biological rules do not change. Earlier schema saves reject explicitly.
- ADR-S5-05: metrics have versioned definitions, units, owners, evidence cursors and coverage. Snapshot gauges represent the exact committed observation boundary, not interpolated continuous values. Event counts/flows use half-open time windows [start,end). Persist sufficient count/sum/min/max/last samples for explicitly sample-weighted time buckets; never call a sample-weighted mean a time-weighted integral. Missing observations are gaps, not zeros. Trip success remains undefined until a trip-start/end contract exists.
- ADR-S5-06: improve TD-03 only with a proved derived optimization. An older edit with the exact same box as a newer edit has no effect on any current classification: the newer operation overwrites every point of that box. A disposable query index may therefore retain only the newest identical-box edit. Keep every authoritative edit, event and parcel, and replay every edit chronologically during validation. Rebuild the index on restore. Test against an unfiltered ordered reference, interleaved overlaps, thin walls, material volume, SDF, clearance and rollback. Do not replace authority by sampled occupancy or claim general history compaction.
- ADR-S5-07: bounded APIs page history/entity/time-series results and use explicit world, owner, time and EventId filters. SQLite indexes support these access patterns; a query cannot advance time or consume RNG. All biological fixtures retain ENGINEERING_FIXTURE labels. Full in-memory fact retention remains explicit and measured; no months-long bounded-memory claim follows from S5.

## Primary storage references

- [SQLite atomic commit](https://sqlite.org/atomiccommit.html): transaction recovery and underlying filesystem assumptions.
- [SQLite WAL](https://sqlite.org/wal.html): WAL commit/recovery, same-host storage and checkpoint behavior.
- [SQLite synchronous setting](https://sqlite.org/pragma.html#pragma_synchronous): FULL synchronization at commits.
- [SQLite download](https://sqlite.org/download.html): pinned 3.54.1 amalgamation, SHA3-256 92281c86e2957f9b9305890f9ac04204caa7b677cc868dc326d942689df28e30.

These references justify engineering storage choices, not biological parameters. Power-loss durability still depends on the OS/filesystem/device honoring synchronization; actual process termination and injected I/O failures are the automated test scope.
