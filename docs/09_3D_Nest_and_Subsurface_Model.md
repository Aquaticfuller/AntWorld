# AntWorld｜自主三维建巢与地下环境模型 v0.1

**设计归档版本：** v0.5（2026-11-08）  
**地位：** 研究与工程规格草案，**尚未开始正式开发**；数学形式和离散精度为候选，需要原型与文献标定。

> **v0.6 决策更新：用户已选定方案 A「有序参数化几何编辑 + 局部 SDF 缓存」，不再把 A 与 B 并列为未决主路线。详细工程设计见 `10_Parametric_Geometry_Implementation.md`、`11_Cpp_Unity_Geometry_Interface.md`、`12_Geometry_Prototype_Test_Plan.md`。本专题早先的比较文字仅作历史背景。  
**目标物种：** *Lasius niger*（黑园蚁），明确标识其他蚁种研究的适用边界。

## 0. 本专题的八个不可违背原则

1. **真实三维**：地下不是二维剖面伪装；水平投影交叉的两条通道没有真实开口时绝不连通。
2. **底层世界独立**：C++ Simulation Core 计算材料、可通行空间、蚂蚁位置、挖掘与微环境；Unity 不修改世界物理状态。
3. **局部规则**：个体只依据其可感知、可达与已学习的局部线索挖掘；无全图最优建巢算法给工蚁发布蓝图。
4. **实际动作**：挖土→形成空腔→工蚁携带土粒→弃置或回填；地下空腔几何与土壤去向必须记账。
5. **同源几何**：渲染 Mesh、碰撞、通行网络均由同一套**权威材料占用状态**派生，不能彼此长期分叉。
6. **有限算力**：精细体积仅用于活跃挖掘边缘、重要巢穴结构与摄像机视野；全 24×24m 不做毫米级全体素。
7. **物种证据边界**：黑园蚁筑造材料沉积的化学信息素研究≠地下掘进完全由相同信息素控制；火蚁的碰撞调节≠黑园蚁已证实规律。
8. **可回溯**：每次建巢进展能关联到工蚁活动、环境条件、被移除/填回的土量、通行变化和游戏时间，供统计与 Game Master 查询。

## 1. 科学依据、可迁移假设与尚无结论之处

### 1.1 黑园蚁直接证据

- Garcia Ibarra 等：17 个年轻 *L. niger* 群体在不同地表温度土柱中挖掘约 100 天。较高温度下巢穴更深、更大，巢室分布更深；部分浅层巢室发生回填。**支持**环境改变长期巢形、回填可能存在，**不直接提供**逐只工蚁选择挖掘点的完整决策算法。DOI: 10.1111/1365-2656.14040；开放数据说明：https://doi.org/10.23708/ZJTSDI （多个原始数据文件目前标为 restricted，未获取，不得假称已进行定量拟合）。
- Khuong 等 (2016)，*Stigmergic construction and topochemical information shape ant nest architecture*，PNAS，DOI: 10.1073/pnas.1509829113：*L. niger* 土粒沉积筑造中的局部化学刺激与体型模板可以形成柱、顶盖和三维筑造。**支持**局部反馈可产生结构；**不证明**同一参数可直接套到地下移土开隧道。

### 1.2 其他物种的启发，必须显式作假设处理

- *Solenopsis invicta*（火蚁）小群体准二维隧道实验：碰撞频率可调节挖掘参与度，简单元胞自动机可再现特定挖掘率阶段；物种、空间维度、土壤条件均与本游戏不同。DOI: 10.1098/rsif.2022.0597。
- *Atta vollenweideri*（切叶蚁）：土壤湿度影响挖掘偏好与效率，在高水分区域可能停挖避免进水；其具体含水量与阈值**不得直接移植到 L. niger**。DOI: 10.1371/journal.pone.0095658。
- *Camponotus socius*、*Pogonomyrmex badius* 等铸模研究：不同深度巢室、倾斜/弯曲通道与连接网络；支持真正三维结构及物种特定形态，不能直接将其巢室尺度当成黑园蚁参数。DOI: 10.1093/jis/5.1.9；10.1093/jis/4.1.21。

### 1.3 本模型首版需要自行测试的假设

- 在某种局部拥挤、幼体需求和微气候条件下，工蚁启动挖掘的概率如何变化。
- 巢室何时从通道侧壁的多次局部开挖中形成，而非预设房间。
- 挖掘选择的角度、方向、通道宽度与现存空腔/岩石之间的关系。
- 不同土壤参数下的挖掘耗时、运土容量、塌陷/封堵概率。
- 连接新空腔时，网络流量和幼体位置如何响应。

## 2. 真实尺度、坐标系与分块

- **唯一世界坐标**：米 (m)、右手或 Unity 约定坐标方向需在 C ABI 明确；建议对外共享 `x=东、z=北、y=向上`，地表为函数 `y_surface(x,z)`，深度 `d=y_surface-y`。
- 质量保存 kg（精细土粒可换算 mg）、时间保存确定义整数模拟 tick + 时间单位、温度内部单位明确（Kelvin 或 Celsius，跨接口统一）、能量 J、体积 m³。
- 地表规模确定为 24m ×24m；`2m × 2m` **分块粒度仍是候选工程参数**，不是生物学规则。
- 地下不能与 2m 地表块同分辨率；巢穴在该块内有独立、可跨块的三维稀疏体积索引与连接图。
- 世界边界应区分：可实际模拟的材料域、玩家可观察域、外围生态边界条件；不应让边界成为生物学意义上的无形墙，至少要有外部迁入/资源通量规则。

## 3. 地下几何：统一权威、分层缓存

### 3.1 决定性的架构约束

**权威是材料占用/空腔几何与连续的编辑历史，不是导航图，也不是 Unity Mesh。**

首版推荐实现：

1. `BaseSoilMaterial`: 粗粒度土层的材料和初始占用，含石块、不可挖根系等障碍。
2. `NestGeometryEdits`: 可持久化、有顺序的局部挖除 / 材料回填记录；可用沿曲线扫掠的切除体、腔体形状或局部细体积改动表示。
3. `SparseOccupancyCache / SDFBricks`: 在活跃挖掘区域缓存材料/空气状态及距离查询；缓存从 1+2 构建，**不是独立事实库**。
4. `DerivedNavigableVolume / NestGraph`: 从权威可通行空腔几何更新，满足蚂蚁身体与负载的净空条件。
5. `RenderMesh / CollisionMesh`: 从同一几何版本构建，允许异步落后一小段，但必须带版本号和同步屏障，碰撞不能滞后到允许穿墙。

> **v0.6 已决策**：采用 **A（初始材料 + 有序参数化挖除/回填编辑为权威，局部 SDF 只作缓存）**。B 可作为长期风险备选，不是第一版平行实现路线；任何切换需要新的架构决策记录。两种表示不能同时作为可独立修改的权威。

### 3.2 精度预算（仅工程候选）

- 长距离地下土壤温湿度场：约 10–25 cm 采样为候选；重要巢区局部细化，巢室温湿度从周围边界与气体交换派生。
- 活跃挖掘区域：候选 1–2 mm 采样；优先几何解析查询而非无条件体素化每个巢室。
- 示例：一个 64 mm 边长、2 mm 间距的体积砖为 32³=32,768 单元；单通道 4 字节约 128 KiB，100 个约 12.5 MiB（未含索引、网格、halo及多字段）。实际需要按材料占用/温度等不同精度分离。
- 每次挖掘不是每个 tick 全量网格化；对累计编辑越过阈值的 dirty brick 局部生成 Mesh，碰撞/导航由权威几何即时验证。

### 3.3 巢穴图结构

- `Chamber`: 稳定 ID、体积、几何边界、位置、环境统计、内部生命实体与历史用途标签。
- `Tunnel`: 稳定 ID、中心线、沿程截面、曲率、净空、坡度、材质、流量和与 chamber 的连接。
- `Portal`: 实际三维连通开口、尺寸、通行限制；仅空间投影交叉不产生 portal。
- `Frontier`: 当前可到达的土壤—空气界面，存储可开挖状态、局部几何法向、邻域环境与作业量。
- 网络/巢室划分是几何派生的索引。巢室类型（育幼、废物、休息）仅由真实占用和工作活动推导，不是决定挖掘的蓝图。

**几何一致性的原子步骤：** 完成挖掘提议→校验材料/连通性/负载→提交权威几何与土壤物料事件→更新局部导航有效性和版本→发布网格脏区与可视事件；任何失败回滚本次编辑与物料变化。

## 4. 蚂蚁如何挖掘：个体局部决策与实际动作

### 4.1 候选动作流程

1. 已存在空腔中的工蚁探测到邻近、可触达的土壤界面（`Frontier`）。
2. 根据其生理状态、可接触界面的可挖掘性、局部空间拥挤、已知幼体需求及局部微环境，决定是否尝试挖掘。**不读取全世界未探访区域的最佳位置。**
3. 沿局部界面移除一份体积 `ΔV`，耗费时间和能量；产生对应的 `SoilParcel`（或合并批次）并放在身体负载中。
4. 负载达到容量或当前工作结束时，沿真实可达通道将材料运往可弃置/回填位置；路径由当前通行图给出，且负载影响通行净空/速度。
5. 材料在指定地点沉积；可形成地表土堆、局部回填/封堵或在允许的筑造行为下形成土粒堆积形态。
6. 局部几何更新后，其他工蚁可能进入新空间；拥挤、通风、湿度与空间工作机会随之变化。

> 工程上可每次挖掘提交 `SoilParcelBatch`，无需为每粒沙子生成 Unity GameObject；但对每批的干土质量、含水量和位置必须记账。

### 4.2 局部挖掘倾向函数：先做最小形式

\[
U_i(f,t)=b_{species} + w_s S_{soil}(f)+ w_c C_{local}(i,f)+w_h H_{micro}(f)+w_b B_{local}(f)+w_m M_i(f)-\theta_i
\]

其中 `f` 为个体可触达的挖掘界面，`S_soil` 是可挖性、`C_local` 是局部碰撞/拥挤线索、`H_micro` 为微气候线索、`B_local` 为局部幼体/空间需求、`M_i` 为该个体已有局部经验，`θ_i` 为响应阈值。选择开始工作可用概率模型；具体 `w` **不是文献真值**，先做开关消融与方向性实验。

- 安全优先：体力不足、不可挖材料、无法站立/施力、路径不可返回、可能打通水源等条件会使候选不合法；初版水源风险先设保守规则，非宣称蚂蚁预知洪水。
- 任务连续性：工蚁挖掘—装载—运土期间保留高层任务惯性，危险信号才可优先打断。
- 不出现“整窝蚂蚁收到巢室设计图”或“用户在地图点房间，蚂蚁立即建造”。
- 回填可由土粒沉积事件形成，不能凭空将旧通道标记为封闭；封堵时必须同步更新真实占用和连通性。

### 4.3 土壤质量守恒、体积与密度

对于一次从原位土壤移除的微体积 `ΔV_inplace`：

\[
\Delta M_{dry}=\rho_{dry,bulk}\,\Delta V_{inplace}
\]

`rho_dry,bulk` 是土壤干容重，不能与矿物颗粒真实密度混用。需要另外追踪水质量 `ΔM_water`，从而区分潮湿材料与干土质量。

\[
M_{soil,initial}=M_{soil,remaining}+M_{carried}+M_{deposited}+M_{exported}
\]

若压实改变体积，则允许体积改变但质量不能凭空增加。含水量变化应进入独立水收支账。首版可以不表现单颗粒碰撞和颗粒流体动力学；优先保证干土/水质量与物料位置的一致性。

### 4.4 巢室如何涌现，而非预制

- 初始新蚁后/幼小群落可自带合法的初始巢室；不违反自然建群过程。
- 工蚁对可触达界面的局部反复扩挖，若一段隧道某位置横向持续被开挖，则空腔截面增大，最终几何分类为巢室。
- 将 `Tunnel`/`Chamber` 视为随几何变化更新的形态标签，不能用“该位置被标为育幼室”直接生成其预定大小。
- 若形成回路，图结构按实际连通开口更新，可产生两条可行路径；必须验证交叉但不相交的不同深度通道不误连。

## 5. 土壤、温度、水分与地下空腔

### 5.1 土壤材料状态

`SoilMaterialCell/Layer`：土质类别、干容重、孔隙率、含水量、热容、导热系数、入渗能力、可挖难度、障碍/根系标记、可选的保守稳定性阈值。岩石与重要根系可作为真实三维障碍对象。

这些参数在首版都属于**物理近似**，除非有具体材料测量值，不得称为真实地区测量。

### 5.2 温度场：由气候驱动的地下响应

首版建议采用低频土壤热传导（多分辨率）并用边界条件连接地表昼夜/季节温度：

\[
\rho c\,\frac{\partial T}{\partial t}=\nabla\cdot(k\nabla T)+q_{source}
\]

这是标准连续介质热传导方程，求解只应在粗土壤场与巢穴附近必要局部运行；巢室空气温度由周围土壤、出入口空气交换以及空腔容积关联。首版可以暂不模拟完整自然对流。统一温度单位与时间步长，并测试数值稳定、能量变化方向。

### 5.3 水分：区分土壤含水与巢室空气湿度

`θ_soil`（体积含水率）与 `RH_chamber`（空气相对湿度）是两个不同变量。雨水可沿地表入渗，移动到下层土壤，改变巢室边界的蒸发和湿度。

完整多相水分输运可采用 Richards 方程，但首版不应直接引入昂贵的全三维非饱和流体求解。推荐低频保守型简化水账：

- 每土层/区域计算入渗、向下排水、侧向交换与蒸发，通量逐步保存且不得产生负水量。
- 当水到达已连接的空腔，计算局部流入/积水，按照连通与高程传递到邻室；**不能忽略实际的门槛和阻挡**。
- 微湿与高湿对挖掘可能有不同影响，但黑园蚁的函数和阈值需标定；不要把切叶蚁的实验土壤含水百分比直接复用。

保守水收支：`rain + initial_storage = infiltration_storage + cave_storage + runoff + evaporation + outflow`（统一量纲，按时段计算）。

### 5.4 结构稳定性与坍塌

第一版只实现必要的几何有效性规则：最小净空、最小局部覆盖厚度、不可挖岩石/根、潜在的过薄壁与危险空腔检查。**不宣称这等价于真实土力学**。真实坍塌、泥石流和复杂地下通风作为后续阶段单独建模。

## 6. 同步更新：物理、导航、渲染、统计与 AI

一次合法 `ExcavationCommitted` 应包含：`WorldId, SimTick, AntId, FrontierId, GeometryEditId, BeforeVersion, AfterVersion, RemovedDryMass, WaterMass, ExcavatedVolume, ChangedAABB, PathConnectivityDelta`。

刷新顺序建议：

1. C++ 主线程按稳定顺序接受挖掘候选，验证物料和局部空间约束；合法编辑提交。
2. 将同一几何版本用于碰撞/净空校验，并标记旧导航区域失效；阻断过期的已不合法路径。
3. 局部重建 `NavRegion/Portal/Graph`，与几何版本绑定；通路被阻断或新连通时发出事件。
4. 将 dirty geometry batches 发给 Unity，按距离/重要性决定网格与碰撞的可视更新节奏。Unity 没收到最新 Mesh 不能改变权威导航。
5. 更新受影响巢室的体积、环境场耦合、空间占用及可派生用途标签。
6. 记录物料账、巢室体积/隧道长度变化，产生时间序列。Game Master 读数据和引用事件，而非直接给工蚁新建命令。

**跨线程及跨程序边界**：暴露具有版本号的只读批量快照；旧数据快照不得用于新版本中穿墙的运动控制。

```text
core/spatial/   SoilMaterialField, SparseSolidField, GeometryEdits, ChunkIndex
core/nest/      NestVolume, Chamber, Tunnel, Portal, Frontier, SoilParcelBatch
core/digging/   DigCandidate, DigAction, SoilTransport, FillAction, GeometryCommit

core/scheduling/DirtyRegionQueue, NearFarUpdate, EventDispatcher
core/metrics/   ExcavationLedger, NestMorphometry, MicroclimateHistory
api/            NestQuery, GeometryDeltaBatch, NestEditEvent
```

### 必须稳定保存的对象

- `FrontierId`, `NestId`, `ColonyId`, `AntId`, `GeometryEditId`，各自携带有效世界/巢穴命名空间。
- `GeometryVersion`，防止将旧导航/碰撞当作当前事实。
- `SoilParcelBatch`: 干土质量、水质量、来源位置、当前携带者或弃置位置、材料类型。
- `SoilHeat/Water`: 土壤环境有自己频率和空间精度，不必随每只工蚁每帧重算。
- `NestUsageAnalytics`: 幼体数量、巢室温湿度、工蚁活动时长、隧道流量、回填/土量历史。

### 逻辑与渲染隔离

C++ `NestGeometry` 是真相；Unity Mesh、透明剖切面与科学观察图层仅是呈现，**切换剖切角度不得改变土壤、巢穴结构或工蚁可通行性**。

## 8. 多精度、时间加速与离线模拟

- 高优先级精度由真实事件决定：活跃挖掘前缘、窄通道碰撞、幼体搬运、即将打通空腔和可能进水，均可提升模拟精度，**即使玩家没有看着那里**。
- 非活跃远距离地下区域保存持久巢穴几何、个体 ID、状态及重要事件；可通过离散挖掘完成事件推进，但必须记录耗时、投入个体与土壤收支。
- 对一个在低频模式下开挖的新隧道，不能只在玩家靠近时临时生成“之前已经挖好的隧道”且无形成事件。
- 允许几何/导航频率与渲染更新频率不同；允许重要个体高精度历史与低精度可视同时存在。
- 暂停/加速、保存/加载/离线推进应当具有相同的材料质量、连通和可达性校验。

## 10. 原型实验与验收

| ID | 初始条件 | 检查项 | 验收标准（工程层） |
|---|---|---|---|
| X1 | 两个不同深度但投影交叉隧道 | 空间/导航 | 未真实开口时不可通行；挖通后才新增连接 |
| X2 | 多只工蚁挖掘同一界面 | 土壤/并发 | 无重复移除同体积；质量账和编辑版本一致 |
| X3 | 挖土后携带/弃置/回填 | 守恒 | 干土、含水量变化均入账，不能凭空增加/消失 |
| X4 | 工蚁在合法边界持续挖掘 | 三维形成 | 空腔与通行体积逐步增长，无预设巢室蓝图 |
| X5 | 改变地表温度和土层条件 | 行为/环境 | 可解释的温度梯度；方向性响应需多随机种子并参考黑园蚁实验 |
| X6 | 固定雨量并改变土壤入渗 | 环境/积水 | 水收支误差在数值容差内，地下积水只经有效路径传播 |
| X7 | 在同一世界转剖面/透明/跟随 | 视图/一致性 | 真实个体、路径、巢穴几何与统计均不受镜头改变 |
| X8 | 同一初值倍速/离线/正常推进 | 时间/LOD | 质量与连通不变式始终成立，生态统计差异符合模型随机性 |
| X9 | 保存/加载并继续挖掘 | 持久性 | ID、编辑顺序、拓扑版本、物料账恢复一致 |
| X10 | 500–2000只蚂蚁的负载试验 | 性能 | 分别记录 Core、网格/碰撞更新、Unity渲染及存档耗时，目标值再依据硬件定 |

### 禁止的“虚假通过”

- 预先生成整套漂亮巢穴，再给工蚁添加只负责播放挖掘动画的工作。
- 工蚁尚未把材料从地层移走，巢室体积已经凭空增长。
- 动态网格和逻辑导航数据彼此不一致，却因为摄像机没看到而不计失败。
- 把其他物种的参数当黑园蚁真实测量并宣称已科学验证。
- 只给玩家显示一条不断变大的“巢穴等级”，但无法查询具体通道、巢室、物料与建造历史。

## 11. 建议下一轮讨论的未决设计

1. **权威地下几何的技术实现**：`参数化编辑+局部SDF缓存` vs `稀疏体素占用为权威`；哪种更容易保证原型连通、土量与高效修改？
2. **第一版挖掘物理真实性等级**：保守几何约束，还是需要早期引入坍塌/土力学？建议先保守约束。
3. **巢穴微气候**：先使用低频土层温湿度近似还是直接实现复杂土壤水热输运？建议前者，并预留替换接口。
4. **首个验证场景**：是否先做“单蚁后初始巢室+10–30只工蚁的小块三维土柱”，验证挖土与搬运后再叠加完整 24×24 m 世界？建议如此，仅作为技术实验，不改变整体开放世界设计。
5. **参数标定来源**：*L. niger* 2023 年受限开放数据能否通过作者/数据平台获取，以标定巢穴形态与温度响应？
