## The 30.4863 ms foreground cut

The admitted inherited St. Petersburg R1 depot-8 session 1 sample 159 has a 30.4863 ms cut at day 86 and event cursor 61,720. The neighboring cuts are 0.1038–0.1667 ms, and the other enabled execution at the same cut took 0.0643 ms. This is a measured hard failure. The earlier code captures aggregate observer time. It has insufficient per-operation attribution to distinguish a CSV stream flush from descheduling, allocation, paging, or a stall in a state read. SQLite restore is measured separately and cannot by itself account for that foreground interval. No correction or exclusion is applied to the sample. The diagnostic maximums are retained for each process. [Exact old observation](../../experiments/s6_4_final_core_readiness/performance/foreground_violations.csv)

## Bounded path to a decision

1. Keep the old estimator and hard limits in production. Keep the 96-window alternative review-only. Its synthetic exact-boundary false-pass interval extends beyond the proposed 5% ceiling, and the full 34-cell plan would consume 52,224 processes before separate overhead work. The result gives no basis for adopting that plan yet. [Reserved synthetic controls](../s6_4_final_core_readiness/PERFORMANCE_MEASUREMENT_QUALIFICATION.md)
2. With live hardware admission, use the predeclared three sentinel cells and eight matched windows. One A/A pair and one A/B pair per cell per window require 96 child processes, with order balanced across windows and at least three sessions. The sum of the three measured workload medians implies about 7.5 minutes of child runtime on this host before admission and scheduling gaps. Use a proposed 20-minute cap on active collection, keeping all attempts and returning `INCONCLUSIVE` if the fixed design does not fit. Instrument each synchronous state read and output batch using one monotonic clock. Record thread CPU during the same interval, VFS write and sync, durable application file sync, reopened checkpoint, worker count, byte authority and acquisition cost. Record the signed wall/CPU residual without assigning it to scheduling. Escalate to an allocation or OS scheduler trace only in a separate trace arm with measured perturbation. Every real 20 ms exceedance remains a failure.
3. Use a held-out instrument test with known delays at distinct phases, such as a 2 ms capture addition, a 10 ms post-capture sync addition and a 25 ms foreground addition under quiet and heavy-tail controls. Keep injected runs outside all release samples. The pilot fails as an instrument if a known foreground overrun is missed, if a post-capture delay is classified as foreground, if authority or work count differs, or if clean and near-boundary effects cannot be distinguished at the planned cost. Estimate attainable precision and cost from the fixed window sample and account for correlation within host sessions. A short pilot can test phase discrimination and runtime budget. It cannot directly certify a rare-error bound. Any larger matrix needs a precomputed sample and time budget, explicit inconclusive region, and independent approval. A hard foreground exceedance is never excused by A/A or a confidence interval.
4. Keep both existing performance qualifications and the distinct new format workload visible. If a proven code bottleneck emerges, compare identical inputs and canonical state across real writes and restore and only then request a fixed admitted collection. Otherwise close the measurement study as `INCONCLUSIVE`. No repeat is used to select a passing subset.
