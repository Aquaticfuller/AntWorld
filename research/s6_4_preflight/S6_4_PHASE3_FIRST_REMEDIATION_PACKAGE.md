# First remediation package — condition-specific egg timing

**Proposed after Phase 4 authorization.** The first task is an opt-in BR-04 egg-stage timing implementation and assay. It uses a measured fixed-temperature regime and the existing persisted egg-duration field. It has one narrow prediction, the cohort egg duration conditional on hatch, accompanied by a full-cohort competing-outcome check. It leaves BR-04 open for stage distributions, temperature response, nutrition-dependent progression and integrated viability. Independent biological acceptance of this first task requires the held-out warm-egg cohort in `VAL-BR-04`. [BR-04 protocol](INDEPENDENT_BIOLOGICAL_VALIDATION_PLAN.md#br-04--active-thermal-and-nutrition-dependent-development)

## Why this task comes first

B06 Table 2 p. 169 measures *Lasius niger* egg duration by population and temperature. This is the closest accepted quantitative counterpart to a current timing field. At the nominal 25 °C arm, actual egg mean temperature was about 24.7 °C and reported egg means were 16.7 d for Borisovka and 15.7 d for St. Petersburg. The ordinary long-term engineering fixture sets 2 d. In the same Core the egg clock counts eligible elapsed time, and the model has no measured thermal context. A small host-side resolver can bind a stage timer to the measured condition and evidence without new biological state or an extrapolating thermal law. Existing accepted data support a scoped calibration reference. Both published population results were already used in the audit. [B06 Methods pp. 166–168 and Table 2](https://doi.org/10.1023/B:JOEY.0000033808.45455.75) [Accepted scale comparison](EVIDENCE_CONFLICTS.md#b1-c05--development-time-and-diapause) [Frozen long-term fixture](../../cpp/apps/s6_3_1_fixture.hpp#L55)

BR-02 has observations of mouth contacts and bout timing without recipient dose and uptake trajectories. BR-05 has activity observations and resting respiration in separate contexts. BR-01 lacks matching body stores, reserve flux and per-egg export. Those gaps make a joint numerical change to delivery, energetic cost or fecundity harder to isolate and independently assess. Egg timing is the first testable subtask. Component data acquisition for BR-02 and BR-05 can proceed alongside it. [Blocker dependencies](BIOLOGICAL_GAP_PRIORITY.md#evidence-dependencies-and-research-order)

## Candidate model and input contract

Use a deterministic condition-specific duration `D_g` for the egg stage, where `g` identifies the measured population/cohort, constant admitted egg-temperature regime and comparable founding conditions. For a living egg with known entry time `t0`, eligible progress is `min(1, (t - t0) / D_g)`. Existing eligibility, death precedence and stage commit semantics remain part of the predictor. Later-stage rules are the frozen comparator's. This candidate estimates only a conditional cohort mean from the rounded published mean. Individual variance, developmental failure and the unconditional hatch curve remain distinct outcomes.

| Input | Initial documented use |
| --- | --- |
| B06 near-24.7 °C Borisovka egg row | Primary development reference. 16.7 d gives 1,442,880,000 ms using 86,400,000 ms/d. Preserve source precision and comparator uncertainty. |
| B06 near-24.7 °C St. Petersburg egg row | Exposed population sensitivity comparator. 15.7 d gives 1,356,480,000 ms. Keep this population and its uncertainty separate. |
| S6.3.1 long-term fixture | Frozen comparison with 2 d egg, 3 d larva and 2 d pupa timers. Keep all other resolved settings identical in a paired assay. Header defaults belong to an independent engineering regression. |
| Actual setup metadata | Record population/cohort, measured brood temperature and its acquisition resolution, stage entry interval, moisture/water access, recorded feeding, source and cohort identifiers and eligible egg counts. Use measured reserves or a declared initialization distribution if evaluating hatch viability. |

Add an explicit assay profile with `profile_id`, exact condition ID, population, temperature with unit and measurement semantics, moisture/feeding context, source DOI and table locator, duration in source units, converted integer ms, estimate status and provenance hash. Reject an absent, ambiguous or inapplicable profile before constructing or mutating an assay world. Admit a recorded regime only when the preregistered temperature and condition match passes. The warm candidate provides no interpolation, offset for a different population or cold result. A missing match remains an incompatible comparison. Label the effective fixed timer as a derived assay candidate until independent validation. Keep pre-existing fixtures and defaults under their current provenance.

For a later BR-04 model compare condition-specific stage clocks with an active-range cumulative stage rate `dP_s/dt = r_s(T, Z_s)` for recorded nutrition state `Z_s`. A degree-day or other response curve needs sufficient measured temperatures, distinct stage endpoints, explicit nonprogression and held-out regimes. This package uses one documented condition and a population sensitivity contrast. It does not estimate a thermal threshold or a nutrition response.

## Implementation boundaries and proposed changes

1. Add an opt-in assay executable, proposed as `cpp/apps/antworld_s6_4_egg_timing.cpp`, its small tested `resolve_egg_duration` profile resolver and a build target. Resolve the constant regime and convert source days to `SimTime` with checked integer arithmetic. Verify the requested assay input, source IDs and output manifest before advancing. Record a unique world/seed/run and profile fingerprint. Keep the unmodified comparator path available in the same runner.
2. During setup, pass the resolved `PhysiologyConfig::egg_duration` to `WorldRuntime::enable_physiology` for each directly initialized egg or founding queen used in this assay. Direct seeded eggs must have a documented entry time at initialization. Unknown-age eggs require an interval/left-entry comparison and cannot silently become newborns. Existing offspring construction copies the maternal `p.config` at birth. Verify inheritance by a post-birth `query_physiology` or checkpoint read. No schema addition is necessary for this design. The existing checkpoint serializer stores the resolved duration. Attach immutable host provenance keyed by run/world and profile hash. The current `PhysiologyEnabled` fact carries setup information but does not carry the duration profile. Recover effective values from state and retained provenance. ## Controls, sensitivity and acceptance

**Control freeze.** Use Phase 2 `c3cb3d0c02940420fd9e0bb4028628c7a9b19a9b`, Core tree `277cc8e78cc1acd1cf4a74bf39d08dfdb6a99c69`, and the existing S6.3.1, R1 and S6.3.4 receipts. Retain exact control profiles, seeds, outputs and negative arms. Include old 2/3/2-day long-term timing, header seconds-scale tests, no external food, ordinary balanced and scarce protein at eight and 32 workers, eight-worker depot-food failures and the 32-worker 180-day sustained reproduction case. Preserve the cold nonprogression observations as outside this admitted egg regime. Compare paired candidate/legacy runs at the same cutoff without changing fertility, mortality, nutrition or duration outside the egg stage. [S6.3.1 controls](../../S6_3_1_RESULTS.md) [Durable ecology](../../S6_3_4_RESULTS.md)

**Budget feasibility check.** The existing funded egg starts with 500,000,000 nJ, 200 µg water and an empty crop. The cited long-term fixture's baseline lineage cost is 1 nJ/ms and water loss is 1 µg/h. At these settings an unfed egg has about 5.79 d of energy and 8.33 d of water in isolation. The egg stage does not acquire energy through the current absorption branch. These are exact-model implications from the ledger and unit conversion, with rounding in days. They expose a competing death before the longer candidate clock can finish in that setting. Retain such deaths in the paired integrated stress arm. Do not change funding, debit or survival to obtain hatches. A separately labeled technical timing sentinel with sufficient engineering reserves can test the scheduler. It supplies no biological reserve estimate or hatch probability. [Egg funding](../../cpp/include/antworld/core/long_term.hpp#L12) [Fixture and lineage configuration](../../cpp/apps/s6_3_1_fixture.hpp) [Absorption eligibility](../../cpp/src/physiology_internal.hpp#L64)

**Sensitivity.** Use published reference values for each population in their documented conditions. Propagate printed precision, measurement cadence and any identified source uncertainty with its original definition. Compare the exact fixed-timer boundary and inspection-time scoring. Report candidate response to plausible starting-store and stage mortality uncertainties using explicitly labeled sensitivity profiles and paired seeds, separate from the primary profile. If the required budget cannot be supported by matched evidence, the joint biological prediction remains blocked.

**Regression tests.** Add setup tests for exact day conversion, invalid or ambiguous regime, unit mismatch, overflow and rejection before world mutation. Test directly seeded and endogenous egg duration, age at entry and ownership. Use boundary tests just before, at and after the clock, including exact-time depletion and absorption order, stage carry-over, and death before hatch. Test mid-egg and terminal snapshot restoration, next scheduled event, hash and committed facts with different advance partitioning. Verify inherited larval/pupal settings and existing conservation and replay tests. Compare legacy artifacts byte-for-byte where the historical runner defines that comparator. Technical sentinel and stress outcomes get separate result fields.

**Independent biological endpoint.** Freeze model, selected population, condition match, complete cohort risk set, source transformations and margins before receiving `VAL-BR-04` outcomes. Compare the candidate and frozen control to hatching intervals, full-cohort hatch incidence and cause-specific losses, with whole-queen or source-cluster resampling. Use the conditional mean only when a measured compatible cohort and enough hatches exist. Set timing and viability margins from measurement repeatability and intended scientific relevance independently of validation outcomes. Missing matched input or outcomes, no hatches, unclear sampling or a confidence interval crossing the margin gives a blocked or inconclusive result. The B06 mean constrains the candidate profile and cannot test independent predictive accuracy.

**Performance.** Run the current Core regressions and admitted S6.2 and S6.3.4 benchmarks where relevant, with the new observer off and on. Keep the 512→2,048 controlled `<=6x` growth contract and the frozen durable-history publication, restore, memory and query limits for their original workloads. On identical biology configurations compare observer overhead and fact/checkpoint bytes. On changed egg timing report wall time and total scheduled/committed work over the same simulated horizon, separating expected extra egg exposure from cost per event. Measure advance, archive capture/submission, publish, WAL, restore, memory and stage-query costs. Freeze a host admission and a paired run budget before executing the new long-duration assay. Retain rejected and failed runs. [S6.2 performance admission](../../S6_2_RESULTS.md) [Frozen storage workloads and budgets](../../docs/64_S6_3_4_Frozen_Durable_History_Protocol.md#frozen-workload-and-host-budgets)

**Failure and rollback.** Reject the package for unsafe setup, bad ordering, conservation or deterministic restore failures, broken frozen controls or failed applicable performance gates. Keep measured biological mismatches and mortality as results. An independently unsupported or failing clock stays experimental and leaves BR-04 open. The deployment rollback uses the existing runner/configuration for new trials, retains original and candidate artifacts and archives each completed run with its own resolved settings. Do not reinterpret an existing checkpoint with the alternate timer. Escalate any need for new Core state, thermal feedback, stage nutrition or changed checkpoint semantics to the next review.
