# Stage B publication and measurement implementation

The untimed qualification smoke exposed redundant durable commits and raw I/O at daily cuts. The Stage B reader keeps all facts and cuts defined by the frozen protocol. Its v2 sidecar writes the same typed records and stable IDs, with a bounded sparse encoding and the same metadata digest chain. No authoritative storage file or codec changed. The v1 sidecar remains readable and continues to use raw records on append.

## Sidecar v2 and durability

The SQLite application ID and manifest identity are unchanged. User version 2 adds an optional encoding inside the payload BLOB. If its first byte is nonzero or the BLOB is empty, it contains the original record stream. Otherwise byte zero is followed by a four-byte little-endian raw length. Each subsequent group has an eight-bit mask with the least significant bit corresponding to the first raw byte. In mask order, store the original bytes at positions with a set bit and restore zeros at the other positions. The final group may have fewer than eight bytes. The cut digest covers the exact stored BLOB and the original ordered metadata. This representation reconstructs the canonical bytes for every fact. It is selected only when smaller, with at most 400 KiB input and under 451 KiB extra scratch. Large payloads take the raw path.

The app uses a separate SQLite WAL with FULL synchronization. A short group of up to 16 cuts and 1 MiB of raw input is written transactionally. An individual larger cut uses its own transaction. Writes inside an open group are staged, with no public durable cursor advance until SQLite commits. The app flushes before publishing a checkpoint anchor, and the benchmark times the final flush. The current group is rolled back if a staged write fails. Recapture resumes from the last durable cursor. Intermediate cut snapshots from a rolled-back group may be unavailable and the host records an incomplete observation. The Core history remains authoritative. A closed, anchored sidecar is the portable export. An interrupted open sidecar may need its matching WAL before reopening. Live external readers were outside the benchmark and analysis use the closed exports.

The benchmark starts an isolated native process per scheduled row to measure a sample-local peak RSS before the checkpoint audit. Each child pins its measured work to the logical CPU chosen by the existing version-2 instrument. The collector remains on the other cores. Setup, observer initialization, time spent advancing, timed observation and SQLite publication, checkpoint and restore are recorded separately. Off arms run the same advances and byte-identity audit. Native session and row order, admission, CPU and sensor telemetry are retained. The reported WAL size is a tail observation before close. SQLite's automatic checkpoint threshold is 256 frames, with a 4 MiB post-reset journal retention limit. The WAL size can exceed that threshold during a transaction.
