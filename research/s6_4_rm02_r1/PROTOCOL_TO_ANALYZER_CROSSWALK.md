# RM-02 R1 performance gate reconciliation

The review uses the Phase 0 design, the protocol frozen at `8ca0705f3282c1de227e9b30046ae6949459fbdb`, and the executable and raw data lineage accepted at `d5667c7c15d61f14c09480ba55a0d58fdc461a48`. The Phase 0 design assigns 20 ms to incremental foreground copy and submission at the fixed cuts and lists background output separately. The Stage B protocol keeps that scope and requires actual committed sidecar writes inside the on-arm total. The historical analysis extended the per-cut maximum to terminal drain. The R1 predicate uses only the measured per-cut maximum for that check.
