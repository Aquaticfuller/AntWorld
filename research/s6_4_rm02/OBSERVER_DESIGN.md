# RM-02 read-only observer proposal

**Design submitted for review.** The first implementation request would cover a host-side reader in an isolated engineering assay. It would use the reviewed Core, configurations and workloads. The reader has no authority to schedule an event, consume randomness, activate a care profile, change an input or add a canonical fact. [Core audit](CORE_SOURCE_AUDIT.md) [BR-02 protocol](VALIDATION_PROTOCOL.md)

## Minimal read path

1. Start from an explicit test manifest or a reviewed checkpoint. Record run and lineage IDs, `WorldId`, the Core commit/tree, model/schema version, seed, resolved fixture configuration and the input checkpoint digest. Select the observation windows and focal individuals before looking at outcomes. Use the same windows, inputs and host advancement cuts in both observer arms. An unsliced baseline comparison checks that the extra cuts themselves preserve semantics.
2. After `advance_to` returns successfully on the owning thread, capture a closed cut from `summary()` and read `events_after(cursor, 256)` through `next_event_id - 1`. Use `encode_event` and EventId order for canonical linkage. A read can also consume an already published history cut with its matching state frame. Retain typed facts for gifts, relevant optional care phases, rejections, absorption, life-stage/death and competing intake, resource and egg uses. The observer observes existing profiles only. `NutritionTransferred` supplies mass and identity even in worlds without the care observation profile.
3. At predeclared cuts, read detached `query_ant` and `query_physiology` copies for a bounded focal set and `nutrition_snapshot` for exact global balance. These are cut observations. Use the existing S6.2 boundary reconstruction as a diagnostic oracle in controlled fixtures. If a per-event before/after value can be reconstructed from a starting state, known schedule and all intervening facts, mark it `RECONSTRUCTED`, provide the input range and check it against the next authoritative snapshot. Where that proof fails, retain the exact committed amount and the whole-cut states, with a missing per-event state. Reading the cut alone cannot observe what happened between same-timestamp donors.
4. In small engineering assays with known explicit proposals, or at designated decision-boundary cuts, a detached `pending_events()` snapshot can link `ScheduledId` to the target and request. This is a full queue copy, so dense production-like runs use facts and bounded focal snapshots. Do not repeat contact sampling inside the model, guess undisclosed selections from the eventual recipient, or enable an existing profile just to get more observations.

The first implementation can reuse actual sample members and selections already reported by an enabled care profile, with their limited definition. `inspection::Scope` is useful as an existing targeted-queen diagnostic comparator. Its precommit vector push can allocate and its target validation can throw. Keep it out of the proposed general reader. Its earlier rollback test establishes state recovery after a failed advance, while the new host reader must also preserve normal progress when observer I/O fails. ## Observation records and linkage

Use integer `sim_ms`, `ug` and `nJ`, retaining all four mass components. Keys include `run_id` and `world_id`, the donor and recipient's stable entity IDs when known, the source `ScheduledId` and applicable `EventId` and revision. Distinct restored continuations can reuse a WorldId and later event numbers, so use lineage and the reference cut digest when joining them. Timed care adds its bout ID. Each record declares its source and coverage.

| Record | Minimum fields and definition | Available in the minimal reader |
| --- | --- | --- |
| Opportunity | Decision/wake ID, donor ID and stage/caste, sampled candidate IDs and their stage/caste if known, modeled physical reach or observed contact definition, risk-set coverage, compatibility known/unknown and action context | Existing care-profile Opportunity or validated S6.2 reconstruction in its fixture. A host-observed geometrical neighbor at a cut can be reported separately. Examined count is computational work. |
| Selection / pending | Wake and selected-action IDs, program, candidate and chosen recipient, requested mass, reason/alternative when known, cut time | Existing care Selected, known pending action or controlled explicit proposal. With legacy facts alone, actual successful recipient is known at resolution, while pre-resolution alternatives and other selections may be missing. |
| Resolution | Source, outcome, donor/recipient, event order, request if known, actual component mass, stage/caste, committed, rejected or canceled status | Use one `NutritionTransferred` as the mass authority per gift. Join a care terminal fact for timing and context. Keep generic `ActionRejected` records with an explicit unknown target when provenance is unavailable. |
| Uptake | Subject, source and committed `PhysiologyUpdated`, active pulse timing when known, consumed mass vector, crop/body energy/water/tissue before and after, losses and boundary status | Exact consumed vector. Read or reconstruct validated compartment states at cuts. A known death or stage event remains a separate transition. True per-gift identity in mixed crops is unavailable. |
| Ledger cut | Cut identity, scope, geometry/schema and checkpoint/frame digest, external input, reserve/available/cargo/nest/crop components, body/tissue and losses, converted carbohydrate energy and total dissipation | Detached snapshot and committed source facts. Report component and energy residuals against the authoritative cut. |

Record `COMMITTED_FACT`, `CUT_SNAPSHOT`, `RECONSTRUCTED` or `UNOBSERVED` on the relevant fields. A known executed transfer attempt with a matched rejection has zero **committed** mass. A known zero pulse has zero consumed mass. `NO_SELECTION` requires a captured selection decision with a different or empty action. `CANCELED` requires a documented cancellation. Unknown kind/target, absent sampled identities, occlusion and writer gaps remain explicit missing categories. An outstanding action or uptake at window end is right-censored if it is still at risk. A missing resolution after a queue entry vanished is not automatically a zero or a recorded cancellation. Identify same-time rows by source and event order, never by timestamp alone.

Use exact component arithmetic to reconcile each resolved gift's equal debit/credit where the two states are observable. At cuts, check `introduced == accounted` and `energy_input_nj == body_energy_nj + dissipated_energy_nj`, including dead stores, funded births and all sinks. Conserve what the model actually stores. Record total absorption from a recipient's mixed crop independently of gift history. Link a pulse to one specific gift only in a controlled, verified isolated-dose window. ## Remaining instrumentation gap

The read path above can be implemented independently of any new Core tap. A full decision risk set and exact event-boundary pre/post states will still be missing in some profiles. If that prevents a defined assay, the follow-up design would request approval for bounded diagnostic copies at three existing boundaries.

- At the nutrition decision, copy the actual sampled identities and already evaluated eligibility predicates, then link the action ID once inserted. Record where the policy never sampled. Preserve actor order and sampling work.
- At the resolution dispatch, copy the actual request, rejection category and available donor/recipient snapshots around the existing transaction. A capture from before the donor gate is required to distinguish its failures from receiver failures. Include owner cancellation only where the existing code performs it.
- At the absorption branch, copy the settled pre-pulse and actual post-pulse compartments and committed amount. Do not add a per-gift provenance mechanism to the model.

These copies would go to fixed-size, preallocated records owned by the host, with no world callbacks, queries, re-evaluation, allocation, I/O or exceptions on the tapped path. A capacity miss records a loss in host metadata. Publish only after successful `advance_to` and reconciliation with existing facts, using the source IDs from that call. Discard the call's provisional rows if the Core rolls back. The proposed taps require their own review. The initial host reader may leave these fields `UNOBSERVED` and use tests or an acquisition assay that match the observed subset.

## Save, restore and failure behavior

Keep a separately versioned sidecar with the manifest, committed read cursor and observation coverage. Flush outside the Core transaction. Link a sidecar cut to the world history prefix and authoritative checkpoint/frame digest. Reopen at the last verified matching sidecar cursor after restore and deduplicate by run lineage and record identity. A restored simulation can continue with a missing or invalid sidecar. The evidence reader reports that gap and its extent. Lost observer output never affects a world commit. Do not infer pending state from canonical facts alone. ## Acceptance tests proposed for a later engineering implementation

| Test | Acceptance |
| --- | --- |
| On/off against identical input, and matched sliced/unsliced advancement | Exact time/revision, stage, positions, crop/body, resource and energy ledger, RNG state, next IDs, watermark and sorted pending events at common cuts. Exact canonical facts and state/trace hashes. Exact exported checkpoints for the small fixtures, and equal frame bytes and streamed canonical fact digests for dense runs. |
| Controlled success, partial and negative cases | Known component gift and next pulse reconcile. Retain no selection, zero-mass matched rejection, zero-uptake pulse, full receiver, depleted donor, incompatible demand, wall, cross-colony, stale movement, duplicate proposals, competing donors and death before/at absorption. Check that a zero-request submission is rejected before scheduling. Include worker-to-queen/larva and already-enabled care feeding. Deduplicate care/transfer facts and retain unknown legacy timing. |
| Same-time events | Environment death/stage/pulse versus later resolution, two donations to one receiver, and intake/birth alternatives in a single timestamp. Preserve order and validate balances. Mark unreconstructable sub-cut fields as unknown. |
| Checkpoint and live history parity | Save and restore before resolution, after a gift and before the next pulse. Compare queue, RNG, canonical history, frame and exact continuation in both arms. Confirm mixed-crop rows and interrupted care stay correctly labeled. |
| Fault and coverage | Exercise failed advance, foreign run, reader overflow, malformed/absent sidecar, write error and repeated restart. No sidecar from a rolled-back call is accepted. A reader failure leaves authority and normal simulation outcomes identical and exposes missing evidence. |

## Proposed measurement budgets

Freeze these engineering budgets before the later implementation is measured. They apply to the observer, while the accepted Core workload, host admission and ≤6× TD-01/TD-08 gate remain the comparators.

- Use 256 facts per read page, up to 64 preselected individuals for intensive cut snapshots, and at most 4 MiB of observer-owned staging and queue memory. Propose a 64 MiB sidecar quota per diagnostic run. Record quota/overflow, affected intervals and exact missing-row counters when known. Treat affected endpoints as incomplete. The standard throughput arm must fit without losing required coverage.
- For fully matched admitted 512/2,048 workloads and a declared long-running nutrition fixture, require observer-enabled median total advance plus reader/export wall time ≤1.10× the matched off arm and P95 ≤1.20×, with P99 reported. Target P95 ≤5 ms and maximum ≤20 ms incremental foreground copy/submission at the fixed cuts and ≤16 MiB additional process peak RSS. Report reader, state queries, encoding, background output, scan work, I/O bytes and restore/sidecar rejoin separately. One full nutrition ledger per predeclared cut is sufficient. No full-world scan per wake, candidate or pulse in the dense arm.
- Repeat on/off in paired ABBA/BAAB blocks with an off/off host repeatability control. Use the frozen host admission, workload identities and uncertainty procedure for the inherited Core gates. Preserve all slow and incomplete samples. Run release on the admitted host with the same code, configuration, seeds and facts for each pair. Retain exact replay first. If repeatability or coverage is inadequate, report inconclusive and locate the reader cost without changing the biology or the existing gates.
